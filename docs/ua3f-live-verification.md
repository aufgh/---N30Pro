# UA3F 升级后的实机实验

日期：2026-10-02（Asia/Shanghai）。在用户已升级的 N30 Pro 上测试。认证账号、密码和完整认证请求没有读取或写入本报告。

## 方法

电脑存在 FlClash TUN，所有实验套接字显式绑定路由器 LAN 的物理以太网接口，包括 IPv4 和 IPv6；DNS 直接询问路由器。测试从 LAN 发出，没有把路由器自身 curl 的结果当成 LAN 接管的证明。

明文 HTTP 使用 [httpbingo 的 User-Agent 回显](https://httpbingo.org/)验证。非标准端口测试使用路由器上的独立临时 uhttpd，仅监听环回地址；客户端访问 RFC 文档地址的 18080、18081 端口，经真实 LAN TPROXY/hev/UA3F 路径后，在路由器 OUTPUT 临时 DNAT 到该回显服务。因此这一部分验证非标准端口接管和 UA 改写，不冒充真实校园网服务器上的端口测试。

另外创建仅匹配实验源地址、源端口和目的地址的 nft 跟踪/计数规则。检查 TPROXY 命中、直接转发计数、UA3F 出口标记、TTL/Hop Limit 和 UDP/443 出口计数。所有临时 nft 表、跟踪进程和回显服务均在结束后清理，没有修改认证配置。

## 结果

| 项目 | IPv4 | IPv6 | 判断依据 |
|---|---|---|---|
| 公网明文 HTTP/80 UA 改写 | 通过 | 通过 | 不同实验 UA 被回显为统一配置值 |
| HTTP/18080、18081 UA 改写 | 通过 | 通过 | 每个端口发送 Android/Windows/iOS 三种不同标记，12 次均改写成功 |
| LAN HTTPS/443 经 TPROXY | 通过 | 通过 | HTTPS 200；内核 trace 命中两个地址族的 TPROXY，直接转发计数为 0 |
| 代理出口 TTL/Hop Limit | 64 | 64 | 带 UA3F 出口标记的实验连接在 postrouting 命中 64 计数 |
| 未代理 UDP 的 TTL/Hop Limit | 37 → 64 | 37 → 64 | 从客户端设为 37，出口各命中 64 一次，非 64 计数均为 0 |
| UDP/443 拒绝 | 通过 | 通过 | trace 命中 reject，实验 UDP/443 出口计数均为 0 |
| NTP 本地重定向 | 通过 | 通过 | 向文档地址 UDP/123 请求也收到匹配的 NTP 应答，mode=4、stratum=2、leap=0 |
| HTTPS 内 UA 改写 | 没有改写 | 没有改写 | 回显保留两个地址族各自的原始标记；符合未开启 TLS MITM 的设计 |
| 流量卸载 | 关闭 | 关闭 | 软硬件 offloading 均为 0，连接表 OFFLOAD 计数为 0 |

UDP/443 实验客户端得到超时，内核记录显示已拒绝且未从 WAN 发出。此实验验证 UDP/443 拒绝规则，未验证特定浏览器的 HTTP/3 回退速度。NTP 重定向请求使用不可依赖的文档地址，收到匹配应答能够区分本地重定向与直接访问公网 NTP。

## 发现并修复的重载空窗

使用 IPv4、IPv6 客户端连续请求临时 HTTP 回显服务，同时执行一次 `fw4 reload`。旧脚本两次复现相同问题：IPv4、IPv6 各有一个 SYN 进入直接转发，且各一次请求失败。问题发生在 helper 先 `cleanup` 删除 nft 表和两组策略路由，再读取配置并逐步重建的窗口。

修复保留重载期间的有效策略路由，通过同一个 `nft -f` 事务删除并重建表；新规则检查或加载失败时保留旧表。停止/关闭透明代理仍会清理规则。该机制参考 [nftables 的原子规则替换说明](https://wiki.nftables.org/wiki-nftables/index.php/Atomic_rule_replacement)。

修复后连续两轮同一实验，共 54 次双栈请求，两个地址族的直接转发计数均为 0，请求错误均为 0。完整协议实验也重新通过。修复已应用到当前路由器，原文件备份为 `/root/n30pro-ua3f-tproxy.pre-atomic-20261002`；编译项目同步修复，回归检查位于 `tests/test_ua3f_lifecycle.py`。

## 解释边界

这些实验支持“已测试的 IPv6 TCP 正常经过代理”，不能支持“所有 IPv6 协议都被代理”或“不会再被识别共享”。非 UDP/443、非 NTP 的其他 UDP 仍可直接转发；HTTPS 内 UA、TLS 数据和应用/账号行为仍可观察到。代理被主动停止、尚未启动或配置不兼容时，本版没有强制阻断 LAN 的策略。

没有进行整机重启、UA3F 进程重启期间的并发流量测试、长时间稳定性和吞吐测试。也没有触发或验证认证平台的共享判定，不能把本次结果当成消除共享提示的保证。

实机发现 UA3F 的版本输出为 Development：上一版项目把链接变量改为 `cmd.AppVersion`，但 `main()` 又以 `main.appVersion` 覆盖它。本次恢复上游的 `main.appVersion` 链接设置；这是版本显示修正，当前设备的转发功能不依赖这个字符串，新构建的版本输出仍需以产物验证。
